# hr_recovery_physionet

Analysis code and summary results for:

> Bae J-H. *Recovery onset at the end of the load rather than at peak heart rate yields test–retest stable heart rate recovery after maximal treadmill exercise.* Submitted to the European Journal of Applied Physiology (2026).

## Data

The analysis uses the open registry *Treadmill maximal exercise tests from the Exercise Physiology and Human Performance Lab of the University of Málaga* (version 1.0.1; Mongin et al. 2021), distributed by PhysioNet: <https://doi.org/10.13026/7ezk-j442>.

The raw records are **not** included here. Download `subject-info.csv` and `test_measure.csv` from PhysioNet under its licence and place them in one folder (e.g. `raw/`). The expected SHA-256 checksums are in `results_hrr_resilience_v1/run_info.json`; the code checks them before running.

Participant-level intermediate files (test- and pair-level heart rate recovery, aligned heart rate curves, cross-validation predictions) are also not included, because they are derived records of the registry. They are regenerated by step 1 below; `SHA256SUMS.txt` in each results folder lists their checksums so that a re-run can be compared with the original.

## Running

Python 3.10 with the packages in `requirements.txt`. Figures use the Liberation Sans font. The scripts look for the results folders one level above their own folder (`../results_hrr_resilience_*`), so before running, move the ten `.py` files into a folder named `code_hrr_resilience/` at the repository root; each script then writes to the results folder named above.

```bash
pip install -r requirements.txt
python code_hrr_resilience/hrr_resilience.py raw/          # 1. primary, secondary, sensitivity (seed 42, 2,000 bootstrap resamples)
python code_hrr_resilience/hrr_resilience_robust.py        # 2. post hoc robustness R1–R4
python code_hrr_resilience/hrr_posthoc_r2.py               # 3. Monte Carlo bound, onset-lag strata
python code_hrr_resilience/hrr_artefact_s4.py              # 4. suspect heart rate signal exclusion
python code_hrr_resilience/hrr_oq08.py feat                # 5. exercise-phase peak HR / VO2peak sensitivity
python code_hrr_resilience/hrr_oq08.py v1
python code_hrr_resilience/hrr_extra_v1.py                 # 6. Table 1, reclassification, SEM/MDC, correlations
python code_hrr_resilience/hrr_fig1a_aligned.py            # 7. aligned heart rate curves for Fig. 1a
python code_hrr_resilience/hrr_manuscript_figures.py       # 8. Fig. 1–4 (values asserted against the result CSVs)
python code_hrr_resilience/hrr_graphical_abstract.py       # 9. graphical abstract
```

`hrr_oq08.py` imports `hrr_predict_v2.py` for data loading and its built-in engine checks. That module looks for the raw files in `D:/treadmil/raw` or `~/mnt/treadmil/raw`; edit the `RAW` line near its top to point to your folder. The prediction-model analysis it also contains was not reported in the manuscript.

Each script first verifies its statistical engine (e.g. the ICC(2,1) implementation against the worked example of Shrout and Fleiss 1979) and stops if a check fails. Code comments are partly in Korean.

## Notes

- Recovery onset: definition A = time of peak smoothed heart rate; definition B = end of the load (first time speed fell below peak speed − 2 km·h⁻¹). Windows 60, 120 and 180 s.
- The analysis plan, decision rule (Bonferroni-adjusted 99.17% lower bound > 0.40) and post hoc labels follow the Methods of the manuscript.
- The code was written with the assistance of a large language model (Claude, Anthropic) and checked by the author, as stated in the manuscript.
